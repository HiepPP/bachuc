## Brief

Goal: Port the skill-pins client to a native GPUI crate: the "Skills" composer pill with its pin menu, on agent and draft composers, and the "Skill pins" settings screen.

Change: GPUI shows no Skills pill and no Skill pins settings -> the crate `bachuc-plugin-skill-pins` contributes both and talks to the unchanged server part through its RPCs.

Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): the server part in `hiep-plugins/plugins/skill-pins` stays unchanged. The crate calls it only through these RPCs:
  - `skill-pins.read`: input `{agentId}` (a UUID), output `{skills: string[]}`.
  - `skill-pins.write`: input `{agentId, skills: string[]}`, output `{skills: string[]}`.
  - Settings id `skill-pins`, through `PluginContext::settings`; values `{defaults: string[]}`.
- The crate is `bachuc-plugin-skill-pins` in `packages/desktop-gpui/plugins/skill-pins`. It exports only `pub fn plugin() -> Box<dyn bachuc_plugin_host::NativePlugin>` with `id()` `"skill-pins"`. It depends on `bachuc-plugin-host`, `bachuc-client`, `bachuc-theme`, `bachuc-icons`, `gpui-kit.workspace = true` with no `features` key, `serde`, `serde_json`, `anyhow`, and `log`, never on a view crate.
- Catalog: the three skills `watchtower`, `chase-goal-claude`, and `sequential-thinking` with the labels, short names, descriptions, and warning of `catalog.ts`. Sent and stored lists are in catalog order with no duplicates. An RPC answer with an unknown id is an error, as `skillsSchema` rejects it; saved settings `defaults` drop unknown ids instead (`savedSkillsSchema`).
- Pill: id `skills`, `ShowOnDraft::Yes`, `PillPlacement::Toolbar`, title `Pinned skills`, label `pill_label(skills)`, and `PillBehavior::Popover { flush: true, .. }`. The label is the pinned short names joined by a spaced middle dot (U+00B7), or `Skills` when none.
- Agent composer: the pins come from `skill-pins.read` for the agent. A save publishes the new list at once, then sends `skill-pins.write` and publishes its answer. A failed read or write keeps the shown list and sets the error line.
- Draft composer: the pins are the draft value `{skills}` under the plugin id, read with `ComposerDraft::get`. An untouched draft shows the settings `defaults`. A save calls `ComposerDraft::set("skill-pins", {"skills": next})`, so the host sends `PASEO_PLUGIN_COMPOSER_skill-pins` on create. The server seeds an untouched draft with the defaults itself (`server/draft.ts`).
- Unknown pins: until the list is known, the label shows `Skills` and every catalog row is disabled, as Electron does.
- Planner call (state loading): a pill `state` closure gets only `&App`. Keep the pins in a crate store `Rc<RefCell<..>>` keyed by agent id. When an agent key is missing and not in flight, mark it in flight and start the read with `App::spawn`, which takes `&self`. When the read lands, store it and call `PluginContext::notify`. Equal lists do not notify again (`pins.ts:15`).
- Failed read (lead, from the spec check): a failed per-agent read clears the in-flight mark. It retries only after the next reconnect or plugin state change, so one failure starts no read loop.
- Planner call (cache): keep each agent's list for the contribution lifetime. Clear the store after `ClientEvent::Connected`, so a reconnect reads again. Hold the client subscription in state that a contribution closure captures, so deactivation drops it.
- Menu: header `Pinned for this chat`, the error line in `status_danger` when set, one row per catalog skill, a 1 px `border` divider, then the muted row `Bỏ chọn tất cả`, disabled when nothing is pinned. A toggle keeps the menu open. Rows follow `menu-row.tsx`: min height 28, inset 4, padding 9 by 5, radius 6, `surface2` on hover or focus, label 14 on 18, description 12 on 16 in `foreground_muted` (two lines), the warning in `status_warning`, and a 16 px muted `Check` when pinned. Each row has `Role::MenuItem` and a label.
- Settings screen: id `skill-pins`, title `Skill pins`, icon `Pin`. Loading and error show one muted line with the texts of `settings.tsx:17-19`. `Invalid` shows the section `Skill pins` with a `Reset to defaults` action. `Ready` shows the section `Default pins for new agents` with one switch per catalog skill. The hint is the description, or `<description>. <warn>.` for a skill with a warning. A switch saves `defaults` against the shown revision, and rows are disabled while saving.
- Settings rows (lead decision): build the screen only from `bachuc_plugin_host::ui` (`note`, `section`, `card`, `switch_row`, `action_row`). The crate draws no settings row of its own.
- Literal colors (Planner call): a color with no `bachuc_theme` token is a named constant with a comment that cites its Electron source `path:line`, as `STOP_RED` in `crates/composer/src/composer.rs:43` does. This crate needs none.
- Put each rule in a pure function and test it (`MEMORY.md`, 2026-10-16): catalog order, unknown-id drop, `pill_label`, the toggle result, the draft value decode, the draft or defaults choice, the publish-equal rule, and the in-flight read rule.
- The app registers the crate in TASK-191, so no screen shows it before then.

Expected result:

- An agent composer shows the Skills pill in the toolbar, labeled with the pinned short names, and its menu toggles and saves each skill.
- A New workspace draft shows the same pill, starting from the settings defaults, and a toggle writes the draft value.
- The Skill pins settings screen toggles the default pins.
- Cases:
  - `pill_label` of none -> `Skills`; of `sequential-thinking` and `watchtower` in that order -> `Watch`, the spaced middle dot, `Seq`.
  - A read answer `["sequential-thinking", "watchtower", "watchtower"]` -> stored as `["watchtower", "sequential-thinking"]`.
  - Saved defaults with an unknown id `old-skill` -> the id is dropped, the others kept.
  - A read answer with an unknown id -> the error line shows, and the rows stay disabled.
  - A draft value `{"skills": ["watchtower"]}` -> shows `Watch`; a draft with no value and defaults `["sequential-thinking"]` -> shows `Seq`; no value and settings not ready -> `Skills` with rows disabled.
  - A write that fails -> the error line shows, and the optimistic list stays.
  - Toggling a pinned skill removes it; toggling an unpinned one adds it in catalog order.
  - 100 `state` calls for one unknown agent -> one `skill-pins.read`.

Anti-goal: at most one `skill-pins.read` per agent between reconnects, however often the pill redraws; tripwire; read from the in-flight store test (`read_once_per_agent`) after the store lands and at completion.
