Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): native Rust client, unchanged server part, calls only through plugin RPCs.
- Crate `bachuc-plugin-workspace-spaces` in `packages/desktop-gpui/plugins/workspace-spaces`. It depends on `bachuc-plugin-host`, `bachuc-client`, `bachuc-theme`, `bachuc-icons`, `gpui-kit.workspace = true` with no `features` key, `serde`, `serde_json`, `anyhow`, and `log`, and never on a view crate. Its only public item is `pub fn plugin() -> Box<dyn bachuc_plugin_host::NativePlugin>`, with `id()` `"workspace-spaces"`.
- RPCs: `spaces.catalog` input `{}`, output `{projects: [{id, name, path, viewKey?, workspaces: [{id, name}]}]}`; settings id `spaces` through `PluginContext::settings`, whose values are `{spaces: [{id, name}], members: {key: spaceId}, hosts: {serverId: {spaces, members}}}`. Validate saved values as `validSpaces` does: unique space ids, at least one space, and every member value names a space. Reject a change that breaks this instead of saving it.
- Planner call: GPUI has one active host (`crates/app/src/shell.rs:410`, `switch_host`), so the host key is the active client's `server_info().server_id`, read with the existing `Client::server_info()`. The "All hosts" root set of Electron has no GPUI view; keep it untouched in saved values. The page shows `Client::host().name` as the host label.
- Planner call: one `SpacesState` entity per activation, shared by the filter, menu, strip, and page. It holds the `PluginSettings` entity for `spaces`, the catalog, `busy`, `error`, `load_error`, and the selected Space. TASK-170 drops it on a host switch, so the selection resets then, as it does on an Electron reload.
- Load after `ClientEvent::Connected` and again after each reconnect; then refresh the catalog every 15,000 ms with one request in flight at most. Settings reload on their own on `PluginEvent::SettingsChanged` (TASK-170). After each load, save, or selection change call `PluginContext::sidebar_filter_changed`: with `Some(Next)` or `Some(Previous)` when the selected Space moved right or left, else `None` (`select`, 37-43).
- Saves wait for an in-flight refresh, run one at a time, and set `busy` while they run (`save`, 124-149). A failed save keeps the old values and sets `error`; a conflict error text comes from `PluginSettings::save_error`.
- Filter rules copy Electron: while loading, on an error, or before the host is known, every project is visible and the title is `None`, so the heading stays "Workspaces". `on_swipe` does nothing while `busy` and never wraps. `on_project_added` refreshes, then saves the project into the selected Space unless any member key already names it, and returns `Err` with the controller error or "Unable to assign project to Space. Try again.". `Next` is +1 and `Previous` is -1.
- Menu rules: while `busy` or loading, `items` is empty. Otherwise one item `move` "Move to" with one child per Space, the current Space `checked`; selecting the current Space does nothing.
- Space menu: opens on a secondary click of a tab and selects that tab first. It floats above the tab: width 220, 6 px gap, at least 8 px from the window edge. A click outside or Escape closes it. Pages are menu, rename, remove, projects, and target, with Electron's texts ("Rename…", "Move projects…" with the count of this Space's projects, "Remove…" or "Keep at least one Space", "‹ Back", "Move <project> to", "Remove “<name>”? Its projects move to <target>."). Enter or Save saves a non-blank name; a blank name is never sent.
- Page: title "Spaces", subtitle "<host> · <Space name>", a Refresh button, the rename row, the project cards of the selected Space, the hint "Swipe left or right across the project list to switch.", and the numbered tabs with "+ New". A horizontal mouse drag across the project list that passes `touch_direction` switches Space. A workspace row opens it with `PluginContext::open_workspace`. Keep the page's own membership key, `project_key(<serverId>, <projectId>)`, as Electron does (page 121-125, 141-144).
- Look: tokens and metrics from `bachuc_theme` with the Electron names (`surface0`, `surface1`, `surface2`, `border`, `accent`, `accent_foreground`, `foreground`, `foreground_muted`, `status_danger`). Strip tabs: min width 26, height 26, padding 7, radius 6, 1 px border, accent fill and `accent_foreground` text when selected; container gap 6, padding 10 by 6, top border. Menu: padding 4, gap 2, radius 10, `surface0`, `bachuc_theme::shadow(ShadowSize::Lg, cx)` for Electron's 16 px blur; rows min height 28, padding 8, radius 6, `surface2` on hover, 12 px label, 11 px trailing text with max width 90; the checked mark uses `IconName::Check`. Page: padding 24, gap 12, title 24 semibold, cards padding 16 and radius 12 on `surface1`, buttons padding 12 and radius 8, selected tab border 2 in `foreground`.
- Lists render lazily: the menu's projects and target pages use `uniform_list` with max height 280; the page's project cards are one GPUI `list`. Never toggle `display` from hover; swap the row fill only.
- Every tab, button, menu row, and input gets a role and a label: tabs use `Role::Tab` with selected state and the Space name as label; "+" is labeled "Create a Space"; menu rows use `Role::MenuItem`.
- Keep each rule in a pure function and unit-test it; view code is checked only by reading it (`MEMORY.md`, 2026-10-16).
- The wheel gesture that turns a trackpad swipe into `on_swipe` belongs to the host sidebar (TASK-175, from `packages/app/src/plugins/sidebar/wheel-gesture.ts`), not to this crate.

Expected result:

- With workspace-spaces listed enabled and `Running`, the sidebar shows only the selected Space's projects, the Workspaces heading shows the Space name, and the strip shows numbered tabs and "+".
- A tab click switches Space; a secondary click opens the Space menu; "+" creates a Space and selects it; the project menu "Move to" moves a project; the Spaces page lists the selected Space's projects.
- Cases (port each Electron test named in Design, plus):
  - `add_space` on `space-1` and `space-3` -> `space-4` "Workspace 4".
  - `rename_space` trims; a blank name or a missing id -> `Err` with Electron's text.
  - `removal_target` of the first Space -> the second; of another -> the one before; of the last Space -> `Err("Keep at least one workspace.")`.
  - `remove_space` moves every member of the removed Space to the target.
  - `adjacent` never wraps at either end.
  - `sidebar_membership` finds a legacy `["<host>","<id>"]` key; an unparsable key is skipped.
  - `view_membership` prefers the `["view","<key>"]` member, then the project's sidebar membership, then the first Space.
  - `match_project` matches a view key, then a placement key by its second item, else `None`.
  - Add project: an already assigned project is not moved; a new one gets both the sidebar and the view key.
  - `move_view` also rewrites every legacy key of the same project.
  - Visibility: an error, a load in progress, or an unknown host -> visible; otherwise visible only in its Space.
  - Title: an error -> `None`; otherwise the selected Space name.
  - Menu items while busy -> empty; otherwise one "Move to" with the member checked.
  - `select` from Space 1 to Space 3 -> `Some(Next)`; to the same Space -> `None`.
  - `touch_direction(-80, 10)` -> 1; `(80, 10)` -> -1; `(60, 0)` -> 0; `(80, 60)` -> 0.
  - `host_state` for an unknown server id -> the default one Space; `with_host_state` keeps the root set and other hosts.
  - Saved values that break `validSpaces` -> rejected, nothing saved.

Anti-goal: sidebar filtering stays cheap: 500 calls of the pure visibility rule over 500 projects with 500 member keys take under 20 ms in total in a debug test, so no JSON parse runs per project per frame; tripwire; read when the visibility rule lands and at completion.
