## Brief

Goal: Port the prompt-translate client to a native GPUI crate: the note under each user prompt, the send interceptor that rewrites drafts as English, the Caveman mode pill, and the "Prompt translate" settings screen.

Change: GPUI shows no translation note, no Caveman pill, and sends drafts as typed -> the crate `bachuc-plugin-prompt-translate` contributes all four and calls the unchanged server part through its RPCs.

Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): the server part in `hiep-plugins/plugins/prompt-translate` stays unchanged. The crate calls it only through these RPCs:
  - `translate.translate`: input `{text, cacheOnly}`, output `{translation: string | null}`.
  - `translate.enhance`: input `{text, deferCaveman: true}`, output `{prompt: string}`.
  - `translate.original`: input `{text}`, output `{original: string | null}`.
  - `translate.mode.read`: input `{agentId}`, output `{mode}`; `translate.mode.write`: input `{agentId, mode}`, output `{mode}`.
  - Settings id `translate`, through `PluginContext::settings`, with the nine fields and defaults of `shared/settings.ts:28-38`. A missing field takes its default.
- The crate is `bachuc-plugin-prompt-translate` in `packages/desktop-gpui/plugins/prompt-translate`. It exports only `pub fn plugin() -> Box<dyn bachuc_plugin_host::NativePlugin>` with `id()` `"prompt-translate"`. It depends on `bachuc-plugin-host`, `bachuc-client`, `bachuc-theme`, `bachuc-icons`, `gpui-kit.workspace = true` with no `features` key, `serde`, `serde_json`, `anyhow`, `log`, and `chrono`, never on a view crate.
- Settings state: the crate keeps the current values and `active_since`. It reads them from the `PluginSettings` entity it creates in `contribute`, which reloads on `PluginEvent::SettingsChanged`. When `translate` turns on from off, `active_since` becomes now, so prompts sent while it was off get no new paid translation (`state.ts:10`). When `translate` changes, call `PluginContext::invalidate_timeline`, because the transformer reads it.
- Transformer: id `prompt-note`, item type `user_message`. On `TimelinePhase::Complete`, with `translate` on and a non-empty trimmed `text`, it returns one item `{kind: "prompt-note", version: 1, data: {text}}` and `SourcePlacement { position: SourcePosition::First, text: None }`. Otherwise it returns `None`. It stays a pure function of its input and the current `translate` flag ([ADR-0039](watchtower/decisions/ADR-0039-incremental-timeline-sync-over-throttle-or-budget.md)).
- Renderer: kind `prompt-note`, version 1. The note is cache-only when the item timestamp is before `active_since`. Planner call: a missing or unparsable timestamp counts as cache-only, so it never starts a new paid call. Vietnamese text asks `translate.translate` and shows `EN`. Other text asks `translate.original` and shows `VI gốc` when the original has Vietnamese, else `EN gốc`. A `null` answer shows nothing.
- Note cache: one lookup per text and cache mode, shared by every row, as `createNoteCache` does. A failed lookup is removed from the cache, shows nothing, and a later render tries again.
- Note look (`note-view.tsx:31-35`): right-aligned, padding 12 left and right and 6 below, 12 px text on a 17 px line in `foreground_muted`, the label in weight 600 and a space before the text.
- Interceptor: id `rewrite-english`. It returns `Keep` when `enhanceShortcut` is off or the trimmed text is empty. It returns `Keep` when `rewrites_on_send_key(send_key, rewrite_mode)` is false. It returns `Keep` for a one-line command (`/` or `$` first, no newline) with no Vietnamese. Else it sends `translate.enhance` and returns `Replace(prompt)`.
- Planner call: on an enhance error the interceptor shows the error text with `PluginContext::show_message(.., MessageLevel::Error, ..)` and returns `Cancel`. Electron also keeps the draft and does not send, and it shows the error as the composer's send error (`packages/app/src/composer/index.tsx:1645-1647`); `InterceptOutcome` has no error variant.
- Pill: id `prompt-prefs`, `ShowOnDraft::Yes`, `PillPlacement::Toolbar`, title `Caveman mode`, label the label of the current mode or `Default`, and `PillBehavior::Select` with the seven modes of `modes.ts` in order (`id` is the mode value). The agent composer reads and writes the mode through `translate.mode.*`. The draft composer reads `{mode}` from `ComposerDraft::get`, falls back to the settings `cavemanMode`, and saves with `ComposerDraft::set("prompt-translate", {"mode": mode})`.
- Planner call (pill loading): a pill `state` closure gets only `&App`. Keep the modes in a crate store `Rc<RefCell<..>>` keyed by agent id. When an agent key is missing and not in flight, start the read with `App::spawn` and call `PluginContext::notify` when it lands. Clear the store after `ClientEvent::Connected`. A failed read clears the in-flight mark and retries only after the next reconnect or plugin state change, so one failure starts no read loop (lead, from the spec check). Hold the subscription and tasks in state that a contribution closure captures.
- Settings screen: id `translate`, title `Prompt translate`. Port the three sections, labels, hints, options, and disabled rules of `settings.tsx:62-168`. The model inputs keep a local draft; `Save models` is enabled only when a trimmed draft differs from the stored value, and a successful save clears the drafts. Loading, error, and `Invalid` states follow `settings.tsx:29-53`.
- Settings rows (lead decision): build the screen only from `bachuc_plugin_host::ui` (`note`, `section`, `card`, `switch_row`, `select_row`, `input_row`, `action_row`). The screen view owns the two model `InputState` entities. The crate draws no settings row of its own.
- Icons (lead decision): the settings screen uses `IconName::Languages`, which TASK-195 adds. This TASK also depends on TASK-195.
- Literal colors (Planner call): a color with no `bachuc_theme` token is a named constant with a comment that cites its Electron source `path:line`, as `STOP_RED` in `crates/composer/src/composer.rs:43` does. This crate needs none.
- `has_vietnamese` matches the letter set of `vietnamese.ts:3`, case-insensitive. Put it, `rewrites_on_send_key`, the command rule, the transformer, the note label rule, the cache-key rule, the settings decode, and the `active_since` rule in pure functions and test them (`MEMORY.md`, 2026-10-16).

Expected result:

- A new Vietnamese prompt shows an `EN` note under its bubble; an English rewrite shows its `VI gốc` or `EN gốc` original.
- Enter on a Vietnamese draft sends the English rewrite in `automatic` mode; Mod+Enter sends it as typed.
- The toolbar shows the Caveman mode pill with the current mode, and a pick saves it.
- Cases:
  - Transformer: a `Streaming` item, `translate` off, or a blank text -> `None`; a `Complete` item with text -> one `prompt-note` item, source first.
  - `rewrites_on_send_key`: `automatic` with `Enter`, `None`, and `ModEnter` -> true, true, false; `cmd-enter` with the same keys -> false, false, true.
  - Interceptor: `/compact` -> `Keep`; `$caveman ultra` -> `Keep`; a Vietnamese one-line command -> rewritten; `enhanceShortcut` off -> `Keep`; an enhance error -> `Cancel`.
  - `has_vietnamese`: `cái này là gì` and an uppercase `Đ` -> true; `hello` -> false.
  - Note cache: two renders of one text in one mode -> one lookup; a failed lookup -> retried on the next render; the same text cache-only and live -> two lookups.
  - Note label: a Vietnamese original -> `VI gốc`; an English original -> `EN gốc`; a `null` answer -> no note.
  - `active_since`: `translate` off then on -> it moves to now; on then on -> it stays.
  - A timestamp before `active_since`, and a missing timestamp -> `cacheOnly: true`.
  - Pill label: an agent mode `ultra` -> `Ultra`; an unknown mode -> `Default`.

Anti-goal: one lookup per text and cache mode, however many rows render it; tripwire; read from `note_cache_one_lookup` (100 renders of one note -> one RPC) after the cache lands and at completion.
