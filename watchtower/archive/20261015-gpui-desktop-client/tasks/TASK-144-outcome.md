## Changed

- `packages/desktop-gpui/crates/timeline/src/grouping.rs`: grouping reads each entry once into a private `Fact` (kind, time, message key, edited path, call kind, running state, `(seqStart, seqEnd)` identity). `group_turns`, `build_turn_group`, and `count_calls` keep their signatures and run on facts. New public `TurnGrouper` with `update(entries, turn_active) -> Vec<Row>`, plus `sync`, `rows() -> &[SharedRow]`, `changed()`, `shifted()`, and `key(index)`. It keeps the facts and the rows of each run between syncs, reads again only the entries whose position or `(seqStart, seqEnd)` changed, and rebuilds only the runs that hold a changed entry or whose bounds, start time, turn end, or seal changed. An unchanged turn keeps the same `Rc<TurnGroup>`.
- `packages/desktop-gpui/crates/timeline/src/lib.rs`: `TimelineView::sync` copies only changed entries (`copy_changed`, positional), syncs the grouper, splits only changed assistant entries into segments, and hashes only changed entries (`entry_hashes`). A turn whose `Rc` did not change keeps its old rows and fingerprints. Step fingerprints combine the cached entry hashes. The turn header fingerprint covers only what the header draws (loading state, step count, running step, changed files), so a step body change does not remeasure it. Diff lines and counts are built once per edit change (`diffs`), not on every frame, and the header uses the cached counts. A diff toggle rehashes only the toggled entry. `DiagramReady` remeasures only the rows that show that diagram. The 1 s clock tick does not draw when a sync drew less than 250 ms before (the sync frame already drew the clock). `reuse_entries`, `push_rows`, and the full regroup and hash per flush are gone.
- `packages/desktop-gpui/crates/timeline/tests/grouping.rs`: new `incremental_rows_match_full_regroup`.
- `packages/desktop-gpui/crates/app/src/shell.rs`, `chrome.rs`, `state.rs`: `SidebarData` and `SidebarGroup` borrow the client's agent, workspace, and host lists, so the sidebar copies no list on every frame. Views stay uncached; labels and roles are unchanged.
- `packages/desktop-gpui/Cargo.lock`: not changed.

## Lessons

- The timeline sync was about 17% of busy main-thread time at 15 minutes and was the part that grew with the turn; the frame (layout and paint of the visible rows) is the rest and stays flat. The 15-minute read still sits about 1.5 points above the 2-minute read; the remaining growth is not in the timeline sync.
- `Rc::ptr_eq` on the grouper's turn groups is a cheap way to reuse a turn's view rows; keep the old rows alive while building the new ones, so no new group can take a freed address.
- The GPUI `list` renders only visible items plus unmeasured items in the leading overdraw, so an off-screen header costs nothing to draw; its fingerprint only decides remeasuring.
- `cua_repl` `click([x, y])` on this app takes screenshot pixels (2x), not points; `[330, 647]` opened a sidebar agent instead of the diff row.
- `cua_repl` `scroll(index, dir, pages)` moved about the same distance for 5 and 25 pages; call it several times to scroll far.
- `date -j -u -f ...` on this Mac parsed the time a day ahead; use `date -j -f "%Y-%m-%d %H:%M:%S %z" "<UTC date> +0000"`, and note that the UTC date was a day behind the local date.
- A GPUI window can get stuck drawing only part of its area (here 350 points of 1100) with no zoom; check a screenshot before a read and relaunch if the drawing is cut.
