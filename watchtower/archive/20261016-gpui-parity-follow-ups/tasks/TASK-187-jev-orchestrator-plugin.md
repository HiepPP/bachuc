## Brief

Goal: Port the jev-orchestrator client part to a native Rust crate: the Delegated work panel, the Direct route panel, the two slash commands, the Command Center item, and the `job` timeline renderer.

Change: GPUI shows no jev-orchestrator UI -> `bachuc-plugin-jev-orchestrator` adds the same six contributions as [hiep-plugins/plugins/jev-orchestrator/index.client.tsx](hiep-plugins/plugins/jev-orchestrator/index.client.tsx) (lines 32-94) and calls the unchanged server part through plugin RPCs.

Design: the Electron client is the look and the behavior to match.

Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): the client is native Rust, the server part in `hiep-plugins/plugins/jev-orchestrator` stays unchanged, and the crate calls it only through `PluginContext::rpc_as`.
- Crate `bachuc-plugin-jev-orchestrator` in `packages/desktop-gpui/plugins/jev-orchestrator`. It depends on `bachuc-plugin-host`, `bachuc-client`, `bachuc-theme`, `bachuc-icons`, `gpui-kit.workspace = true` with no `features` key, `serde`, `serde_json`, `anyhow`, `log`, and `uuid` (v4). It never depends on a view crate. Its only public item is `pub fn plugin() -> Box<dyn bachuc_plugin_host::NativePlugin>`, with `id()` `"jev-orchestrator"`.
- RPC shapes, all camelCase JSON:
  - `jobs.list` input `{parentId}`, output `{jobs: [Job], history: [unknown]}`. Decode each job on its own and skip one that does not fit `JobView` (`task.id`, `status`, `message`, `notifyError?`, `attempts[]` with `childId`, `phase`, `profile {name, model, thinkingOptionId?}`, `status?`, `output?`, `checks? [{exitCode: number|null, output}]`). Ignore `history`, as Electron does.
  - `jobs.cancel` input `{parentId, id}`, output `{cancelled: bool}`. A success refetches the list.
  - `direct.profiles` input `{workspaceId}`, output `{profiles: [{id, name, provider, model, modeId?, notes?, effortIds: [low|medium|high|xhigh|max]}]}`.
  - `direct.run` input `{workspaceId, requestId (uuid v4), prompt, allowedProfileIds, allowedModels: [{provider, model, effortIds}], shareWithJev: true}`, output `{agentId, selection {id, name, provider, model, modeId?, thinkingOptionId, featureValues?}, routingMs, usage}`.
  - `direct.status` input `{workspaceId, requestId}`, output `{records: [unknown]}`; a record counts only when `requestId` is a string and `status` is one of `routing`, `creating`, `created`, `failed`, `interrupted` (`asDirectRecord`, 51-61).
- Jobs panel state: poll `jobs.list` every 5,000 ms while the panel view exists, with at most one request in flight; drop the poll task with the view. Cancel shows only for status `queued`, `running`, `needs_input`, or `interrupted`, and is disabled while a cancel runs. Texts copy Electron: title "Delegated work", the hint (90-93), "Request failed. Refresh and inspect the job before retrying.", "Loading jobs…", "No delegated jobs for this agent.", "Cancel and archive children", and "Refresh". A check shows the last 1,200 chars of its output and an attempt the last 2,500 chars, counted in chars, not bytes.
- Direct route state copies `DirectPanelState`: prompt, selected profile ids (at most 8), selected efforts per model key, and the locked request. Key the state by host and workspace, so a host or workspace change starts fresh. Profiles load once on open with no retry; "Retry profiles" reloads. `Route and run` is enabled per `canRoute` (329-336). A run error shows the uncertain-result notice with "Check request status". A record or a run result shows the outcome cards; "Open agent" calls `PluginContext::open_agent`. "Reset for a new task" clears all state.
- `/route` with arguments does not open the panel. It calls `PluginContext::show_message("Use /route without arguments.", MessageLevel::Error, cx)`, as Electron shows the thrown error.
- Planner call: `/delegations` and the slash `context: Agent` open panel `jobs` with `PanelTarget { workspace_id, agent_id: Some(agent), location: None }`, taking the workspace from `SlashInput`, else `PluginContext::active_workspace_id`. With no agent or no workspace, the handler does nothing. `/route` and the Command Center item open `direct-route` for the workspace with `agent_id: None`.
- Panel contexts (lead, from the spec check): panel `jobs` has `PanelContext::Agent`. Panel `direct-route` has `PanelContext::Workspace` with `locations: vec![PanelLocation::Workspace, PanelLocation::Explorer]` (`index.client.tsx:37,53-54`).
- Icons: `direct-route` and `open-direct-route` use `IconName::Route` (TASK-195); `jobs` uses `IconName::GitBranch`.
- Look: map the plugin theme colors to `bachuc_theme::tokens` with the same names (`surface0`, `surface1`, `surface2`, `border`, `accent`, `accent_foreground`, `foreground`, `foreground_muted`, `status_danger`), and sizes to `bachuc_theme::metrics` (`SPACE_*`, `RADIUS_MD` 6, `RADIUS_LG` 8, `FONT_SM` 12, `FONT_BASE` 14, `FONT_2XL` 20, `WEIGHT_SEMIBOLD`). Content padding is 12 compact and 20 otherwise; use 20 on desktop. Set text line height near 1.2 (Electron `lineHeight: 21` on 14 px text is 1.5; copy it where Electron sets it). Use `ui_font_size` so the font scale applies.
- Lists render lazily: each panel is one GPUI `list` with a `ListState`, one item per row group (title block, prompt, each profile row, each effort card, the route button, each notice, each job card). Keep items small, one per visual row group (`MEMORY.md`, 2026-10-15).
- Prompt input: a multi-line gpui-kit `InputState` with min height 120, max length 12,000 chars, placeholder "Describe the task for the new agent", read-only while a request is locked.
- Every button, checkbox row, chip, and input gets a role and a label: profile rows and effort chips are `Role::CheckBox` with checked and disabled state, as Electron's `accessibilityRole="checkbox"`. Never toggle `display` from hover.
- Load after `ClientEvent::Connected`: a request sent before it fails and is not retried (CONTEXT). A panel opened while disconnected shows its error text and loads again on the next `Connected`.
- Keep every rule in a pure function and test that; GPUI view crates have no headless test context (`MEMORY.md`, 2026-10-16).

Expected result:

- With jev-orchestrator listed enabled and `Running` on the active host, `/delegations` opens Delegated work for the agent, and `/route` and "Open direct Jev routing" open Direct route for the workspace.
- Delegated work lists each job with its attempts and checks and refreshes every 5 s; Cancel sends `jobs.cancel` and refetches.
- Direct route builds the same `direct.run` input as Electron and shows the outcome; a `job` timeline item renders as "`id · status`" over the message.
- Cases:
  - `offered_effort_ids("claude-luna-1", [low, max])` -> `[max]`; `("gpt-5", [max, low])` -> `[low, max]` (canonical order).
  - `is_luna_model`: `luna`, `x/luna-2`, `Luna` -> true; `lunar`, `alunax` -> false.
  - Two selected profiles on one model -> one group with the union of efforts and `profile_count` 2.
  - Deselecting the last profile of a model drops that model's selected efforts.
  - `toggled_efforts` keeps the canonical order when adding.
  - `can_route`: prompt of 7 trimmed chars -> false; no profile -> false; a model with no selected effort -> false; a pending run or status -> false; `may_retry_same_request` -> true even with a locked request.
  - `derive_outcome`: run error, status success, and no records -> `may_retry_same_request`; a `created` record -> agent id and selection from the record; a `failed` record -> `may_reset`.
  - A record with `status: "unknown"` or a non-string `requestId` -> ignored.
  - `route_label`: pending -> "Routing…"; retry -> "Retry same request"; else "Route and run".
  - `keyed_checks` gives unique keys for two identical checks.
  - A `jobs.list` payload with one malformed job -> the other jobs still show.
  - `cancellable` true only for the four statuses above.
  - `slash_route_allowed("")` -> true; `("x")` -> false.
  - The `direct.run` input JSON has camelCase keys and `shareWithJev: true`, and `requestId` is a v4 UUID.

Anti-goal: the jobs panel sends at most one `jobs.list` per 5,000 ms per open panel, never two at once, and none after the panel closes; tripwire; read from the `poll_due` and in-flight guard tests and by reading the poll task's ownership at completion.
