# TASK-177 Settings plugin screens

Group: G (writes `crates/settings`)
Class: code

## Brief

Goal: Show the settings screens of the active plugins inside Settings with Electron's header and states, open them on a plugin's `open_settings` request, and list plugin themes in the Appearance theme picker.

Change: Settings has five fixed pages and three themes -> a Plugins group of screen rows below the five pages, a plugin screen page with Electron's plugin id and title header, an `open_plugin_screen` call for the app, and plugin themes after the built-in themes in the picker.

Design: Electron opens a screen from the Plugins page menu in [packages/app/src/screens/settings/plugins-page.tsx](packages/app/src/screens/settings/plugins-page.tsx) (`PluginActionsMenu` line 50, items lines 86-109), routes it in [packages/app/src/plugins/settings/routes.ts](packages/app/src/plugins/settings/routes.ts) (lines 2-5) and [packages/app/src/plugins/navigation.ts](packages/app/src/plugins/navigation.ts) (lines 23-24), titles it in [packages/app/src/screens/settings-screen.tsx](packages/app/src/screens/settings-screen.tsx) (line 1322), and draws its states in [packages/app/src/plugins/settings/index.tsx](packages/app/src/plugins/settings/index.tsx) (lines 83-111, strings in `packages/app/src/i18n/resources/en.ts` lines 2112-2117). The theme picker is `ThemeRow` in [packages/app/src/screens/settings/appearance/appearance-section.tsx](packages/app/src/screens/settings/appearance/appearance-section.tsx) (line 158, plugin items lines 138-147 and 210-218, swatch lines 631-637).

Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): read screens and themes only from `PluginHost::index`. Each plugin draws its own screen; this TASK adds no schema-driven form, because Electron has none.
- Entry point (Planner call, sent to the lead as an owner question): GPUI has no Plugins page (extra Settings pages are out of scope, Q-084), so the Settings sidebar lists active plugin screens under a "Plugins" label below the five pages, one row per screen with its icon and title, in index order. With no active screen, the label and rows are absent and the sidebar looks as today.
- Keep `Settings::new`, `open_project`, `SettingsEvent`, and `load_appearance` working as today: `crates/app/src/shell.rs:1555-1563` matches `SettingsEvent` exhaustively. The private `Section` enum may change, since nothing outside the crate names it.
- Plugin page: header with `page_title`, the plugin id and the screen title joined by the middle dot of `settings-screen.tsx:1322`, then the screen's `AnyView`, built once per (plugin id, screen id) and dropped when the contribution goes. States, in order, each in `foreground_muted` with `note`:
  - Client not connected -> "Connect to this host to open plugin settings."
  - Screen or plugin not active -> "This plugin settings screen is unavailable."
- Redraw the nav rows and the open page on `PluginHostEvent::ContributionsChanged` and `PluginStateChanged`; a screen view redraws itself.
- When the open screen's plugin goes inactive, the page shows the unavailable state and keeps its place; the nav row is gone.
- `open_plugin_screen` selects that screen's page; an id the index lacks shows the unavailable state, never a panic. Electron rejects a screen id from another plugin; the host already scopes `OpenSettings` to the caller's plugin id.
- Theme picker (in this crate because the picker lives in `pane_appearance.rs:263-303`): after the three built-in themes, a separator, then each plugin theme with a 16 px round swatch of its background with a 1 px `border` ring, checked when selected. The trigger shows the selected plugin theme's name and swatch. Picking a plugin theme calls `set_custom_theme(Some(id))`; picking a built-in calls `set_custom_theme(None)` and `set_theme`. Both persist.
- `appearance.json` gets an optional `pluginThemeId` string, as Electron's `pluginThemeId` (`provider.tsx:89-92`); a file without it loads as today, and an id whose plugin is off stays in the file. Add a field `plugin_theme: Option<String>` to `Appearance`: only this crate builds `Appearance` with struct literals (`appearance.rs:245-275`, all with `..Appearance::default()`). `apply` sends it to `set_custom_theme`.
- `watch_plugin_themes` maps each `ThemeContribution` to a `CustomTheme` with id `<plugin_id>/theme/<id>` (Electron `themes/index.ts:135`) and its scheme from `appearance`, calls `set_custom_themes` once at once and again on each `PluginHostEvent::ContributionsChanged`. It needs the host global; with no host it does nothing.
- The app's `theme.cycle` action (`crates/app/src/state.rs:271`) only changes `ThemeChoice`; while a plugin theme is selected the cycle has no visible effect until the picker picks a built-in. Report this; the app is not this group's file.
- New rows use `bachuc_theme` tokens and `bachuc_icons` icons, with roles and labels. Keep each rule in a pure function and test it (MEMORY 2026-10-16).

Expected result:

- With an active plugin that adds a settings screen, Settings shows a Plugins label and the screen row; a click shows the plugin id and title header and the plugin's view.
- A plugin theme appears in the Appearance picker after the built-in themes and colors the app when picked; the choice survives a restart.
- Cases:
  - No active plugin screen -> the sidebar has only the five pages.
  - `open_plugin_screen("edit-diffs", "display")` -> that page shows; an unknown id -> the unavailable text.
  - The client is not connected -> the offline text.
  - The plugin goes inactive while its page is open -> the unavailable text; it comes back -> the view again, built anew.
  - `appearance.json` with `"pluginThemeId": "claude-look/theme/claude-light"` and no such theme -> the stored `ThemeChoice` applies and the id stays in the file after a save of another field.
  - Picking "Light" after a plugin theme -> `pluginThemeId` is removed and the light tokens apply.

Anti-goal: Appearance load and save stay compatible: an `appearance.json` written before this TASK loads to the same `Appearance` values, and `saved_appearance_survives_a_reload` and `every_theme_round_trips` pass unchanged; tripwire; read before the first change and at completion.
