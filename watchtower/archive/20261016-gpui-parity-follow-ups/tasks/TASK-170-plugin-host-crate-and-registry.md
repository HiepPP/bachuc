# TASK-170 Plugin host crate and registry

Group: B (writes the new `crates/plugin-host` and the workspace `Cargo.toml`; `Cargo.lock` is generated)
Class: risky

## Brief

Goal: Add the `bachuc-plugin-host` crate: the `NativePlugin` trait, one typed contribution kind for each kind the ported plugins use, the host context that plugins receive, and gating by the active host's `plugin.list`. View crates and plugin crates build on it.

Change: the GPUI client has no plugin host, so no plugin pill, page, or row shows -> a host entity that activates each registered plugin crate when the active host lists it as installed, enabled, and running, and indexes its contributions for the views.

Design: the TS contract in [packages/plugin/src/client/contracts.ts](packages/plugin/src/client/contracts.ts) (`PluginClientContext` lines 116-186, sidebar project, filter, menus, and section 188-245, header subtitle 246-257, stop button, target, and interceptor 259-302, selection, attachment, and passage 304-338, panels, settings screen, surface, shortcut, and sidebar item 342-400, timeline 402-438, command capabilities and contexts 440-518, settings state 520-532), [packages/plugin/src/client/buttons.ts](packages/plugin/src/client/buttons.ts) (behaviors line 30, `PluginComposerPillContribution` line 111), [packages/plugin/src/contracts.ts](packages/plugin/src/contracts.ts) (theme colors line 56, attachment source line 74, transform result line 99), [packages/plugin/src/attachments.ts](packages/plugin/src/attachments.ts) (item line 10), [packages/plugin/src/client/host.ts](packages/plugin/src/client/host.ts) (attachment search line 12), [packages/app/src/plugins/attachments/model.ts](packages/app/src/plugins/attachments/model.ts) (chip to `AgentAttachment`, line 76), [packages/app/src/plugins/composer/draft.ts](packages/app/src/plugins/composer/draft.ts) (draft env, line 24), and the web registry [packages/app/src/plugins/registry.ts](packages/app/src/plugins/registry.ts) (lines 48-100).

Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): each plugin client is a Rust crate in `packages/desktop-gpui/plugins/<id>` named `bachuc-plugin-<id>`, and it shows only when the active host lists it as installed and enabled.
- Dependency rule: `bachuc-plugin-host` depends on `bachuc-client`, `bachuc-icons`, `bachuc-theme` (for the `ui` module), `gpui-kit`, `serde`, `serde_json`, `anyhow`, and `log`, never on a view crate (`bachuc-composer`, `bachuc-sidebar`, `bachuc-timeline`, `bachuc-command`, `bachuc-settings`, `bachuc-workspace`, `bachuc-explorer`, `bachuc-app`). View crates and plugin crates depend on it, so no cycle forms. Plugin crates call `bachuc-client` directly through `PluginContext::client` for agent and workspace reads; the host does not wrap every client call (Planner call).
- Declare `gpui-kit.workspace = true` with no `features` key; a crate that adds features makes a second GPUI build (CLAUDE.md).
- Workspace `Cargo.toml`: set `members = ["crates/*", "plugins/*"]`; try it with no `plugins/` folder first; if cargo rejects the empty glob, add an empty `plugins/.gitkeep` and say so in the outcome (lead, from the spec check). Try adding `"tree-sitter-markdown"` and, when gpui-kit has it, `"tree-sitter-markdown-inline"` to the `gpui-kit` features for TASK-179. `MEMORY.md` names `css`, `html`, `toml`, and `yaml` as breaking `cocoa`; if markdown breaks `cargo.sh build -p bachuc-app`, leave it out and say so in the outcome.
- The trait stays object-safe: no generic method, no `Self: Sized` method, used as `Box<dyn NativePlugin>`. Contribution kinds are plain structs that hold `Rc<dyn Fn ..>` closures, so they clone cheaply and need no lifetime. Views are `gpui_kit::AnyView` built by a factory with `&mut Window` at use time; the consumer caches the view per contribution and input. GPUI runs on one thread, so `Rc` is right.
- `contribute` runs each time a plugin becomes active on a host. Dropping its `Contributions` deactivates it: entities and tasks the plugin created there drop with the closures, so cleanup is by `Drop` and there is no cleanup callback (Planner call).
- Gating (Planner call): a plugin is active when the active host's `plugin.list` has its id with `enabled: true` and `PluginStatus::Running`. That is the loaded set, the same set Electron gates on through the catalog. List again after `ClientEvent::Connected`, after `PluginEvent::CatalogChanged`, and after `set_client`. Keep the active set through a disconnect, so pills do not flicker; a host switch (`set_client`) deactivates every plugin first. Drop a list response that arrives after a newer list request or a host switch. A list `Err`, for example a missing `daemon.manage` permission, logs a warning and leaves no plugin active.
- Only plugins whose active state changed run `contribute` or drop; the others keep their entities. The index is rebuilt in O(contributions) and emits `ContributionsChanged` once.
- Timeline work stays in proportion to the change ([ADR-0039](watchtower/decisions/ADR-0039-incremental-timeline-sync-over-throttle-or-budget.md)): `transformers_for` and `renderer_for` are map lookups that return a slice or a reference with no allocation, and transformers are pure functions of `TimelineTransformInput`, so the timeline caches results by entry and `timeline_revision`. `timeline_revision` grows only on a contribution change or `PluginContext::invalidate_timeline`.
- Order: contributions keep registration order, plugin by plugin in the order passed to `init`, then in `add_*` call order. Two renderers with the same `kind` and `version`: the first wins and the second logs a warning. Two stop buttons: the first wins.
- `pill_applies` follows `buttons.ts:111`: a draft composer shows only pills with no `workspace_id` and no `agent_id` and with `show_on_draft` `Yes` or `Only`; an agent composer hides `Only` pills and pills scoped to another workspace or agent. The compact rule that keeps toolbar and corner pills in the track stays in the composer.
- `ComposerDraft::environment` returns `PASEO_PLUGIN_COMPOSER_<plugin_id>` keys with JSON-encoded values, as `draft.ts:24` does. `ComposerAttachment::to_agent_attachment` returns the JSON of `pluginResourceAttachmentToAgentAttachment` (`model.ts:76`), with the comment appended only when `commentable` is true and the trimmed comment is not empty.
- `search_attachments` calls the picker's RPC method with `{query}` and decodes `{items}`.
- `PluginSettings` follows `SettingsState` (`contracts.ts:520-532`): it loads on creation, reloads on `PluginEvent::SettingsChanged` for its own plugin and settings id and after `ClientEvent::Connected`, never throws from `save` or `reset`, and keeps the shown values when a save gets `Conflict` or `Invalid`, with `save_error` set.
- `PluginHostEvent` is `#[non_exhaustive]`, so a later variant breaks no consumer. The host emits UI requests as events; the app routes them (TASK-174 and TASK-191).
- Keep each rule in a pure function or a plain struct and test that, because GPUI view crates have no headless test context here (`MEMORY.md`, 2026-10-16). `Contributions`, `ContributionIndex`, `active_plugin_ids`, `pill_applies`, `ComposerDraft`, `ComposerAttachment`, and the settings state changes need no `App`.
- In the Interfaces lines, `Handler<I>` is `std::rc::Rc<dyn Fn(I, &mut Window, &mut App)>`, `ViewFactory<I>` is `std::rc::Rc<dyn Fn(I, &mut Window, &mut App) -> AnyView>`, and `PopoverClose` is `std::rc::Rc<dyn Fn(&mut Window, &mut App)>`; the crate exports these three type aliases. `id` fields are `&'static str`, titles are `SharedString`, and icons are `bachuc_icons::IconName`. Every contribution struct derives `Clone`.
- `ui` module (lead decision, 2026-10-16): one small public module of element helpers, so TASK-182, TASK-183, and TASK-185 do not each copy the settings rows. Draw them as [packages/desktop-gpui/crates/settings/src/ui.rs](packages/desktop-gpui/crates/settings/src/ui.rs) does (`section` line 191, `card` 216, `row` 228, `row_text` 241, `select_trigger` 90), which follows [packages/app/src/components/settings/index.tsx](packages/app/src/components/settings/index.tsx) (lines 35-193). Copy that code; never depend on `bachuc-settings`. `markdown_style` copies the timeline's `markdown_style` ([packages/desktop-gpui/crates/timeline/src/lib.rs](packages/desktop-gpui/crates/timeline/src/lib.rs) line 1313) without the code highlighter. `bachuc-icons` already depends on `bachuc-theme`, and `bachuc-theme` depends on neither host crate, so the new edge forms no cycle. The helpers need `App`, so they are checked by reading, except the pure divider rule of `card`.
