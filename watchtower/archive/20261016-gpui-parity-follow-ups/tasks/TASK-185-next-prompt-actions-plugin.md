# TASK-185 next-prompt-actions plugin

Group: N (writes the new crate `plugins/next-prompt-actions`; the tag comes from its own folder)
Class: risky

## Brief

Goal: Port the next-prompt-actions client to a native GPUI crate: the "What Next" panel that replaces the end of an assistant reply, with its Recap header, prompt cards, and Send, Edit, and New thread actions, plus the auto-run command and the "Next prompt actions" settings screen.

Change: GPUI shows each reply's "What Next" section as plain Markdown with no actions -> the crate `bachuc-plugin-next-prompt-actions` folds it into an action panel and calls the unchanged server part through its RPCs.

Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): the server part in `hiep-plugins/plugins/next-prompt-actions` stays unchanged. The crate calls it only through these RPCs (`contracts.ts`):
  - `prompts.host`: input `{}`, output `{serverId, evaluator: bool}`.
  - `prompts.scope`: input `{agentId}`, output `Scope` `{serverId, agentId, workspaceId}`.
  - `prompts.inspect`: input `Scope`, output `Snapshot` `{enabled, busy, note, warning?, candidates}`.
  - `prompts.send`: input `Scope` plus `key` (one string, or an array of at least two), output `{sent}`.
  - `prompts.start`: input `Scope` plus `key`, output `{started}`.
  - `prompts.toggle`: input `Scope` plus `enabled`, output `Snapshot`.
  - Settings id `send`, through `PluginContext::settings`; values `{backToBoard: bool}`, default false.
  - A `Candidate` is `{key, block, text, why?, source, timestamp, after?, state, thread?, suggestion?, goal?, selection?}`, with `state` one of `ready`, `sending`, `sent`, `unknown`. Decode unknown fields leniently.
- The crate is `bachuc-plugin-next-prompt-actions` in `packages/desktop-gpui/plugins/next-prompt-actions`. It exports only `pub fn plugin() -> Box<dyn bachuc_plugin_host::NativePlugin>` with `id()` `"next-prompt-actions"`. It depends on `bachuc-plugin-host`, `bachuc-client`, `bachuc-theme`, `bachuc-icons`, `gpui-kit.workspace = true` with no `features` key, `serde`, `serde_json`, `anyhow`, `log`, `regex`, `fancy-regex`, and `unicode-normalization`, never on a view crate.
- New crates (lead, from the spec check): adding `fancy-regex` and `unicode-normalization` from crates.io is allowed. Pin exact versions in the crate's `Cargo.toml`.
- Planner call (regex): port each JS pattern with `regex` when it has no look-around and with `fancy-regex` when it has one (`gitAction` uses `(?=` and `(?!`). `gitAction` strips marks after NFD (`unicode-normalization`), as `normalize("NFD").replace(/\p{M}/gu, "")` does. The ported test cases are the contract.
- Transformer: id `next-prompt-panel`, item type `assistant_message`. On `TimelinePhase::Complete`, it splits `text` with `split_next_section`; `None` when there is no eligible section. It returns one item `{kind: "next-prompt-panel", version: 1, data: {title, intro, section, recap?}}`. When the text before the section, after `split_recap`, is not empty, the source stays first with that text; otherwise `source` is `None`. It is a pure function of its input ([ADR-0039](watchtower/decisions/ADR-0039-incremental-timeline-sync-over-throttle-or-budget.md)).
- Renderer: kind `next-prompt-panel`, version 1. A `data` that does not decode renders nothing and logs a warning.
- Planner call (panel model): keep one model entity per agent id in a crate map, shared by every mounted panel of that agent, as the shared React queries are. It holds the scope, the snapshot, `pending`, the action error, and the load error. It reads `prompts.scope` once, and again when the agent's `workspace_id` changes. It reads `prompts.inspect` after the scope lands, when the agent's status changes (`ClientEvent::AgentsChanged`, `AgentFinished`), after each action, and every 2,500 ms only while `note` is `Jev reviewing...` (`inspectionInterval`). Hold the map, its subscriptions, and its tasks in state that a contribution closure captures.
- Busy: `pending`, a load error, `agent_busy` (status not `idle` or `closed`, or attention reason `Permission` from `Client::agent_attention`), or the note `Jev reviewing...`.
- Actions: Edit calls `PluginContext::set_composer_text` with `join_prompts(texts)`. Send first opens the Board surface when `backToBoard` is on (`open_surface("board", OpenSurfaceOptions { plugin_id: Some("board"), .. })`), then sends `prompts.send`. New thread sends `prompts.start`. Each action sets `pending`, clears the error, stores a failure as the error, and reads `prompts.inspect` after.
- Candidate match (`panel.tsx:661-669`): a candidate belongs to a prompt when `after` is set, the item timestamp in ms is greater than `after`, and `block` and `text` are equal. Planner call: a missing or unparsable timestamp matches no candidate, so that panel shows no action buttons.
- Card faces: port the button label and icon rule of `panel.tsx:211-233` and line 317 as one pure function. On desktop `touch` is false, `modifier` is the platform modifier held while the Send button is hovered, and `compact` is a panel width of 600 px or less. Measure the width with a `canvas`, as `crates/workspace/src/workspace.rs:963` does. Both faces reserve width and only one paints; swap them by visibility, never by `display` (CONTEXT GPUI lessons).
- Selection block: shown when the block has a `next-prompts` declaration, more than one local prompt, a candidate for each, and no git action. Port `layout`, `reachable`, `selection_allowed`, the group titles, the row status texts (`panel.tsx:433-444`), and the footer texts (`panel.tsx:537-545`). The selection is per panel view.
- Markdown (lead decision): the Recap values and the intro use `bachuc_plugin_host::ui::markdown`.
- Look: port the sizes, gaps, radii, and token roles of `panel.tsx` (`surface0`, `surface1`, `surface2`, `border`, `foreground`, `foreground_muted`, `accent`).
- Literal colors (Planner call): a color with no `bachuc_theme` token is a named constant with a comment that cites its Electron source `path:line`, as `STOP_RED` in `crates/composer/src/composer.rs:43` does. Here that is the `Suggested` badge fill `#0f7b5f` and its white text (`panel.tsx:180` and `panel.tsx:185`), fixed in Electron for contrast in both themes.
- Command: id `toggle-auto-run`, title `Toggle Jev next-prompt auto-run`, `CommandContext::Agent`. Its `visible` reads a flag set from one `prompts.host` read at activation, true only when `evaluator` is true. Selecting it reads `prompts.host`, `prompts.inspect`, then sends `prompts.toggle` with the opposite `enabled`. A missing workspace id does nothing. A failure shows its error with `show_message(.., MessageLevel::Error, ..)`.
- Settings screen: id `send`, title `Next prompt actions`. Port `settings.tsx:12-55`: the loading and error lines, the `Invalid` reset action, and the switch `Back to Board after send` with its hint. Build it only from `bachuc_plugin_host::ui` (`note`, `section`, `card`, `switch_row`, `action_row`); the crate draws no settings row of its own (lead decision).
- Icons (lead decision): use `IconName::Send` and `IconName::CornerDownRight`, which TASK-195 adds. This TASK also depends on TASK-195.
- Every rule above that does not need `App` is a pure function with a test (`MEMORY.md`, 2026-10-16).

Expected result:

- A reply that ends with a `## What Next` section and an eligible fence shows the reply up to the Recap, then one panel with the Recap header and one card per prompt.
- The latest reply's cards have Send and Edit buttons that work; older replies show the prompts with no buttons.
- Cases:
  - A reply with no eligible section, or a `Streaming` phase -> the transformer returns `None`.
  - A section heading inside a code fence -> ignored.
  - A legacy, a five-field, and a compact Recap -> folded into the header; unknown prose before the section -> stays in the reply.
  - `commit_chip`: `yes, pushed main` -> `pushed main`, done; `no` -> `No commit`; `chưa commit` -> `Chưa commit`.
  - `git_action`: `Commit and push the X changes.` -> `Commit & Push`; `Commit the fix, do not push.` -> `Commit`; a mention such as `fix the Commit button` -> `None`.
  - `parse_prompts`: a `next-prompts` block with an invalid relation -> skipped; a `text` block with `why:`, `thread: new`, and `suggestion: true` lines -> parsed per prompt.
  - `selection_allowed` and `reachable`: a pair inside one exclusive group -> not allowed; a declared combination -> allowed.
  - Card label: `ready` -> `Send`; `ready` with the modifier held over Send -> `New thread`; a `thread: new` candidate -> `Start in new thread`; `sending` -> `Sending...`; `sent` -> `Sent`; `unknown` -> `Check chat`.
  - An agent that is `running`, or that waits on a permission -> every action disabled.
  - `backToBoard` on -> Send opens the Board surface before the RPC.
  - `evaluator: false` -> the command is not visible.
  - A missing item timestamp -> no candidate, no buttons.

Anti-goal: an idle agent sends no timed `prompts.inspect`: with the note not `Jev reviewing...`, the panel model asks for no inspect between agent status changes and actions, and one `prompts.scope` per agent and workspace; tripwire; read from `idle_agent_no_timed_inspect` and `scope_once_per_workspace` after the model lands and at completion.
