Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): native Rust client, unchanged server part, calls only through plugin RPCs.
- Same crate and dependency rules as TASK-189: `bachuc-plugin-board`, no view crate, no other plugin crate, `gpui-kit.workspace = true` with no `features` key, and `plugin()` stays the only public item. Add contributions to the existing `contribute` in `src/lib.rs`. Reuse the `BoardStore` that `contribute` creates; add no second `board.snapshot` poll.
- RPCs, camelCase JSON: `board.timeline {}` -> `{threads, missingStart, olderDropped}`; `board.recaps {days: 7}` -> `{days: [{day, projects: [{key, name, projectId?, entries}]}]}`. Decode each thread and entry on its own; a bad row is skipped and logged.
- Timeline polls every 15,000 ms and Recaps every 30,000 ms, only while that view is shown, with one request in flight at most. The Timeline model recomputes on new data, on a minute change, and on a chart width change, not on every frame.
- Timeline and Recaps rows open the agent with `PluginContext::open_agent_at(agent_id, AgentAnchor::LatestPrompt, cx)`, as `timeline.tsx:401` does. A timeline TASK chip links to Watchtower with `BoardStore::open_task`. The Recaps Copy button writes `recap_day_markdown(day)` with `cx.write_to_clipboard` and shows "Copied" or "Copy failed".
- Planner call (lead, 2026-10-16): the thinking orb is a native GPUI animation, as the owner chose for stop-orb (`watchtower/CONTEXT.md`, "Small plugins"). The board crate draws its own orb and does not depend on the stop-orb crate (TASK-181) or any other plugin crate.
  - Port the seven modes that the settings offer: `solving` (`rubik`), `working` (`orbits`), `searching` (`globe`), `listening` (`wave`), `weaving` (`braid`), `composing` (`ribbon`), `connecting` (`web`), with their helpers, `BASE_PROFILES`, and `PRESETS`. `breathing` and `shaping` are not offered, so skip `ring` and `morph`.
  - Each mode is a pure function `(size, time, options) -> Frame`, where a frame is the depth-sorted dot list (position, radius, ink weight, alpha) plus the line list of `web`. Paint dots as filled circles and lines as strokes on a GPUI `canvas`.
  - `Orb` picks the preset with `orb_preset` and scales it, as `orb.tsx:23-36` does. Ink is monochrome from `inkColor`, dark or light from `bachuc_theme::scheme(cx)`.
  - `OrbAvatar` copies `orb.tsx:46-81`: the avatar at 0.9 of the size, round, at `avatarOpacity / 100`, with saturation lowered toward 0.6 (draw it with reduced opacity if GPUI has no saturate filter), and the orb canvas centered over it at `sphere_canvas(avatar, state)`.
  - Replace the body of `crate::card::running_avatar`: when `orb.enabled` and the run is running and does not need input, draw `OrbAvatar`; otherwise keep the spinner. Request the next animation frame only while an orb is in view.
- Settings screen `thinking-orb`: states loading, error, invalid (with "Reset to defaults" through `PluginSettings::reset`), and ready. Ready shows the enabled switch, the Animation select with the seven states, and the Avatar opacity select from 100% down to 20% in steps of 10, built from gpui-kit components because the plugin cannot use the settings crate.
- Header chip `project`: font 14, mark `round(14 * 1.05)`, padding 1, 4, and 8, radius 6, gap 6, colors from `chip_colors(hue)` with the hue from `BoardStore::hues` by project id. A click calls `open_new_workspace` with `{cwd: project_root_path, projectId, name: project_display_name}`; it is disabled without a root path.
- Corner pills: register three `ComposerPill`s in this order, all `PillPlacement::Corner`, `ShowOnDraft::No`, with no `workspace_id` or `agent_id`. Their `state` finds the run whose `agent_id` equals `ComposerTarget::agent_id` in the store snapshot and returns `None` when none fits.
  - "Remove" (title "Remove from Board", `IconName::X`): a finished run. The press runs `BoardStore::remove`, then `open_surface("board", ..)`, then `BoardStore::close_runtime`.
  - "Remove & New Thread" (title "Remove and Start New Thread", `IconName::SquarePen`): a finished run with `cwd`. The press removes, calls `open_new_workspace` with `{cwd, projectId, name: project}`, then closes the runtime.
  - "Jump To Parent" (`IconName::CornerLeftUp`, color `#f97316`, the one literal color, kept as a named constant with the `remove.ts:29-30` reason): a run whose `parent_agent_id` differs from its `agent_id`. The press calls `PluginContext::open_agent(parent)`; the Electron hidden `parent` surface is not needed.
  - A store error hides every pill, as `remove.ts:238` does. A removal that reports `false` shows "Run changed. Refresh and retry." and a close failure shows "Could not close N thread process(es)." through `PluginContext::show_message(.., MessageLevel::Error, cx)`.
  - Planner call: GPUI pills match by `agent_id`, so the Electron workspace lookup (`remove.ts:74-78`) is not needed.
- Look: tokens from `bachuc_theme` with Electron's names; copy the Timeline and Recaps measures in Design line by line (row height 26, subagent row 18, strip 46, axis 22, label column 230, now line 2 px `status_danger`), each multiplied by the board scale. Done-bar hue colors come from pure functions as `Hsla`.
- Lists render lazily: the Timeline is one GPUI `list` with one item per thread row and per subagent row; Recaps is one `list` with one item per day header, project header, and entry.
- Every row, bar, button, and select gets a role and a label. Never toggle `display` from hover.
- Keep each rule in a pure function and unit-test it (`MEMORY.md`, 2026-10-16). Reproduce JS rounding: `Math.round` rounds halves up.

Expected result:

- Timeline shows the last 24 hours with load strip, axis, fold breaks, now line, thread bars, and the footer; Recaps shows 7 days with Copy per day.
- A running card shows the orb in the chosen state over its avatar; the Thinking orb screen saves the three settings.
- A finished thread's composer shows Remove and Remove & New Thread; a subagent's composer shows Jump To Parent; the workspace header shows the colored project chip.
- Cases:
  - `timeline_model`: the Electron `timeline.test.ts` client cases (breaks, ticks, load, peak, now line).
  - `duration_text(90_000)` -> "2m"; `(3_600_000)` -> "1h"; `clock_text` uses local time.
  - `timeline_notes`: no threads, `olderDropped`, one and two missing starts.
  - `recap_day_markdown` matches the Electron output for an entry with did, branch, and commit and one with none.
  - `orb_preset(16)` -> preset 20 at scale 0.8; `sphere_canvas(32, Weaving)` -> 32 / 0.76.
  - Each of the seven orb modes: a frame has dots sorted by depth with each radius at least 0.3, and two frames at the same time are equal; `web` also returns lines.
  - Pill state: running run -> no Remove; finished run -> Remove; no `cwd` -> no "Remove & New Thread"; parent equal to self -> no Jump To Parent; store error -> no pill.

Anti-goal: the orb stays cheap: 1,000 frames of each of the seven modes at the 32 px preset take under 500 ms per mode in a debug test, and no animation frame is requested while no orb is in view; tripwire; read when the engine lands and at completion.
