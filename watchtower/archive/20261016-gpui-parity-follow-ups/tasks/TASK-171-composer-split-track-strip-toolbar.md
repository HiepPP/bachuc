# TASK-171 Composer split into Electron components, track strip, and toolbar

Group: C (writes `crates/composer`; TASK-172 follows in the same group, so the order ties them)
Class: risky

## Brief

Goal: Split the composer into one Rust file per Electron composer component, and add the Electron track strip, turn metrics pill, diff stat pill, context window meter, queue actions, send error, and toolbar density.

Change: one 1,411-line `composer.rs` with a diff row above the card, no strip, no meter, a cancel-only queue, and fixed pills -> component files that mirror Electron, a docked strip with tasks, subagents, turn metrics, and the diff pill, and the Electron toolbar and queue.

Boundaries:

- Keep the public API: `Composer::new`, `agent_id`, `focus`, `attachment_count`, `Attachment`, `can_send`, `mime_for_path`, and the `ComposerEvent` variants `Sent { text, images }` and `ReplaceWithDraft`. `crates/app/src/shell.rs:1095` compares `ComposerEvent` with `==`, so a new variant breaks nothing there. Add the variants named in Interfaces.
- Keep every existing test of the crate. Move a test with its function when the function moves.
- Mic, dictation, and realtime voice stay out (owner, CONTEXT "Out of scope"). Leave no slot for them.
- Redraw rule: the composer redraws only when its snapshot changes, as `Watched` does today (`composer.rs:67`). Add the strip data to the snapshot through the TASK-169 accessors. Those accessors never scan the timeline ([ADR-0039](watchtower/decisions/ADR-0039-incremental-timeline-sync-over-throttle-or-budget.md)).
- Planner call: the live turn estimate runs only on the 1 s tick of an active turn, never in the snapshot read. It scans back from the end of `Client::timeline` and stops at the active turn's first item.
- Planner call: the diff stat pill and a Paseo subagent row emit events; the app routes them (TASK-173). A provider subagent row shows in the panel but opens nothing, because GPUI has no provider-subagent tab. Detach stays out, as TASK-169 says. Archive uses the existing `Client::archive_agent`.
- Planner call: queue Edit takes the item back, as Electron does (`index.tsx:2233-2259`): `cancel_queued`, then its text goes into the input. `QueuedPrompt` holds text only, so queued images are not restored.
- Planner call: reuse `bachuc_sidebar::StatusBucket` and `bucket_for_agent` for subagent marks, so the composer and the sidebar share one bucket map. Add `bachuc-sidebar` to the composer `Cargo.toml`. `bachuc-sidebar` does not depend on `bachuc-composer`, so no cycle forms. A `SubagentRow` has no permission or attention reason, so pass `0` pending permissions and `None` as the attention reason, with `requires_attention` from the row (lead, from the spec check).
- Planner call: density reads the toolbar width from the last layout, as gpui-kit elements can measure bounds. Keep the rule itself in the pure function of `layout.rs`.
- Send through `send_message` and `enqueue_message`. Show the `Err` text as the send error under the queue, and keep the input text so nothing is lost.
- Colors come from `bachuc_theme` tokens. Amber 500 and red 500 have no token, so name each one as a constant, as `STOP_RED` does (`composer.rs:42`). Values: amber 500 `#f59e0b` and red 500 `#ef4444` ([packages/app/src/styles/theme.ts](packages/app/src/styles/theme.ts) lines 76 and 89).
- TASK-170 is an order dependency only. TASK-172 adds the plugin pills, interceptors, stop button, and attachment sources.
- GPUI view crates have no headless test context (`MEMORY.md`, 2026-10-16). Put each rule in a pure function and test that: snapshot equality, strip visibility, task label, subagent segments, metric parts and tones, live estimate, meter percent, color, and cost, density, queue move target, and send error text.
- Never toggle `display` from hover; swap by visibility (CONTEXT). Give every new button, row, pill, and menu item a role and a label.
- In the Interfaces lines, `cx` means `cx: &mut Context<Client>`.

Expected result:

- An agent with tasks, a running subagent, a finished turn with metrics, and a diff stat shows the 28 px strip at the top of the card: "2/7 tasks", the subagent pill, then the "TTFT 1.2s" and "45 tok/s" metrics pill and `+742 -0` at the right edge, over a 1 px divider.
- The diff row above the card is gone; the diff pill in the strip emits `OpenChanges`.
- Queue rows show Edit, Send now, Move up, Move down, and Cancel, and a held queue shows the Resume notice.
- Cases:
  - No diff stat, no metrics, no task, and no subagent -> no strip.
  - A running turn with no model output yet -> "TTFT 3s" with the U+2026 ellipsis, ticking each second; the tick stops when the turn ends.
  - A turn that ended without metrics -> no metrics pill, even when an older turn has metrics.
  - Usage with no context window data -> no meter; 91 percent -> destructive; 70 percent -> amber.
  - The first queue row has no Move up; the last has no Move down.
  - `send_message` answers `Err("agent busy")` -> "agent busy" shows under the queue and the input keeps its text.
  - Toolbar width below the full floor minus 12 -> condensed; below the condensed floor -> tight.

Anti-goal: the composer redraws only when its snapshot changes, and the live tick runs only during an active turn; tripwire: a test asserts an unchanged snapshot (with tasks, subagents, metrics, usage, and held queue) causes no redraw, and a test asserts the pure tick rule is off with no active turn; read before the split, after the snapshot grows, and at completion.
