# TASK-172 Composer draft mode and plugin slots

Group: C (writes `crates/composer`; runs after TASK-171 in the same group)
Class: risky

## Brief

Goal: Give the composer the Electron draft mode for a new agent, and draw the plugin slots of TASK-170: pills, interceptors, the stop button, attachment sources, plugin slash commands, and plugin composer text and chips.

Change: the composer works only for an existing agent and knows no plugin -> a draft mode with provider, model, mode, thinking, and feature pills, 5 lines, a return icon, and empty submit, plus every composer plugin slot gated by the plugin host.

Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): the composer draws native plugin contributions from `bachuc_plugin_host`, and only for plugins the host reports active.
- Keep `Composer::new` and every TASK-171 item. Draft mode is a second constructor; an agent composer behaves as TASK-171 left it when no plugin is active.
- Draft controls: the model pill lists every available provider's models, grouped by provider, and a pick sets both. The default provider is the first available one; the default model is `default_model`. Mode, thinking, and features reload when the provider, model, or `cwd` changes. Drop a response that arrives after a newer request. With no `cwd`, the draft has no `DraftConfig` and shows provider and model only.
- Planner call: agent profiles (`useAgentProfilePicker`) stay out; GPUI has no profile store.
- Draft submit: the submit button shows `CornerDownLeft`, and an empty text submits. Submit emits `ComposerEvent::DraftSubmit`; the owner reads `draft_submission`, then calls `set_submitting`. While submitting, the input keeps its text, is locked at opacity 0.6, and the primary button shows a spinner.
- The draft holds one `Entity<ComposerDraft>`. Its `environment()` goes into `DraftSubmission::environment`. `set_draft_cwd` sets `ComposerDraft::cwd` too.
- Pill slots: a pill shows when `pill_applies` is true and its `state` returns `Some`. Track pills go into the TASK-171 strip after the subagents, and they count for strip visibility. Toolbar pills go after the attach button, before the agent controls. Corner pills go into `CornerPills`. A draft draws its track pills in a row above the card, and its toolbar pills in the toolbar. Planner call: the GPUI desktop window is never compact here, so `placement` is used as given.
- Pill behavior: `Action` runs `on_press`; in a draft, an `Action` with `new_workspace_panel` emits `ShowNewWorkspacePanel` instead (view.tsx:157). `Select` opens a menu of its options with a check on `value` and calls `on_select`. `Popover` opens its `content` view with no padding when `flush`.
- Interceptors: run in registration order on send and on queue; each sees the text the previous one returned. `Replace` changes the text, `Cancel` stops the send and keeps the input. While they run, the primary button shows a spinner. With no interceptor, the send runs at once with no task.
- Stop button: the first `stop_buttons()` entry replaces the red face; the press still cancels the agent. Props: `size` 28, `icon_size` the toolbar glyph, `cancelling` while the cancel is pending.
- Attachment sources: the attach menu lists "Attach <title>" for each source with a `picker`, after the image item. A pick opens a searchable list with the picker title and placeholder. A pick toggles a chip; a second pick of the same item removes it. Chips show the source icon and title; a commentable chip has a comment field; a chip press calls `on_open` when it is set. Send adds `to_agent_attachment(comment)` of each chip to `OutgoingMessage::attachments`.
- Planner call: the search calls `Client::invoke_plugin_rpc` with `picker.search_method` and `{query}`, and decodes `{items}` into `Vec<AttachmentItem>`. `search_attachments` needs a `PluginContext`, and the host produces no lookup of one by plugin id (reported to the lead).
- Planner call: the composer subscribes to the plugin host itself. `SetComposerText` for its agent replaces the input text and focuses it. `AddComposerAttachment` for its agent adds the chip. The app does not route these two events.
- Plugin slash commands: the menu lists built-in commands, then plugin commands whose name no built-in name or alias claims, then daemon commands no earlier entry claims. `Workspace` and `Agent` commands need a workspace; `Global` ones always show. On submit, `/name args` with no attachment calls `on_submit` with the trimmed args and clears the input.
- Redraw on `PluginHostEvent::ContributionsChanged` and `PluginStateChanged`, and on the TASK-171 snapshot rule. Pill `state` closures run in render, not on every client event.
- Keep each rule in a pure function and test it: slot split by placement, pill visibility, the press rule, the interceptor chain, the stop button pick, the chip toggle, the slash merge and match, and the draft config with and without `cwd`.
- In the Interfaces lines, `cx` means `cx: &mut Context<Client>` for `Client` methods.

Expected result:

- A draft composer starts 5 lines tall (21 + 4 x 21 = 105 px), shows the provider and model pill, then mode, thinking, and feature pills, and a return-icon submit that works with empty text.
- With a fake plugin that adds a track pill, a toolbar pill, an interceptor, a stop button, and an attachment source, each appears in its Electron place; with that plugin inactive, none appears.
- Cases:
  - An `Only` pill -> shows on a draft, hidden on an agent composer.
  - A pill scoped to another agent -> hidden.
  - `state` returns `None` -> hidden, and the strip hides when nothing else shows.
  - A draft `Action` pill with `new_workspace_panel` -> `ShowNewWorkspacePanel`, and `on_press` does not run.
  - Two interceptors, `Replace("b")` then `Keep` -> "b" is sent; `Cancel` -> nothing is sent and the input keeps "a".
  - Two stop buttons -> the first one draws.
  - The same attachment item picked twice -> no chip.
  - A plugin slash command named `/clear` -> hidden behind the built-in `/clear`.
  - `/route fast  ` with no attachment -> `on_submit` gets `args: "fast"`; with an image -> it is sent as text.
  - No `cwd` -> `draft_submission` has `config: None`.
  - A features response after a newer provider pick -> dropped.

Anti-goal: with no active plugin, the composer does no plugin work: the slot functions return empty for an empty `ContributionIndex`, and a send with no interceptor starts no task; tripwire: a test for each; read before the plugin slots, after the slots land, and at completion.
