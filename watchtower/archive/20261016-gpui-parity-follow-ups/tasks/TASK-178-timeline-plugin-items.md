# TASK-178 Timeline plugin transformers, renderers, selection actions, accent find ring

Group: H (writes `crates/timeline`; TASK-184 follows in the same group)
Class: risky

## Brief

Goal: Run the active plugins' timeline transformers on changed entries only, draw plugin timeline items with their renderers, show assistant selection actions over selected assistant text, reveal a timeline passage on request, and draw the find ring in `accent`.

Change: plugin items show as a muted "plugin" note, no transformer runs, selected assistant text has no actions, and the find ring uses `ring` -> transformed entries and plugin rows drawn by plugin views, a selection toolbar, `reveal_passage`, and the `accent` ring (Q-098, CONTEXT Defaults).

Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): transformers and renderers come only from `PluginHost::index`.
- Follows [ADR-0039](watchtower/decisions/ADR-0039-incremental-timeline-sync-over-throttle-or-budget.md): per-flush work stays in proportion to the change. Run transformers only for `grouper.changed()` entries, from a cache keyed by entry key with the entry's `seqEnd`, phase, and result. Run them for every entry only when `PluginHost::timeline_revision` or the agent's labels change, which are rare. Renderer lookups are the host's map lookups.
- Planner call: project at the entry level, after grouping. `grouping::TurnGrouper` keeps grouping the source entries, so `incremental_rows_match_full_regroup` and every grouping test stay unchanged. Each entry gets an optional projection: the plugin items, plus the kept source and its place. Electron also groups a plugin row that replaced a tool call as that call (`turnWorkCall`), so step labels and counts match.
- `sync` returns early today when the timeline version and `turn_active` are unchanged (`lib.rs:409`). Add the host `timeline_revision` and a hash of the agent's labels to that check, and sync on `PluginHostEvent::TimelineTransformsChanged` and `ContributionsChanged`. `PluginStateChanged` only redraws (selection actions), with no transform run. Fold the projection into the entry hash (`hash_entry`, `lib.rs:566-590`), so `apply_rows` remeasures only rows whose projection changed.
- Transform rules, as Electron:
  - Input: `item` is `entry["item"]`; `labels` from `Client::agent_labels` (empty map when `None`); phase `Streaming` for a `tool_call` with `status: "running"`, and for the last `assistant_message` or `reasoning` entry while the turn runs; else `Complete`.
  - Transformers of `transformers_for(item type)` run in index order; the first `Some` wins. A result with a `kind` that does not match `^[a-z][a-z0-9-]*$` or a `version` of 0 logs a warning and counts as `None`. A transformer that panics is not caught; plugin code must not panic (no `catch_unwind` in a flush).
  - No `source`: the plugin items replace the entry. `source` `First` or `Last`: the source stays before or after them; its `text` replaces the shown text only of `user_message` and `assistant_message`. `items: []` with no `source` hides the entry.
  - Item id: `<plugin_id>/<item.id>`, else `<plugin_id>/<entry key>/<index>`.
- Daemon plugin items (`type: "plugin"`, `messages.ts:715-722`, merged by `client/src/timeline.rs:365-376`) render through `renderer_for(kind, version)` when the renderer's `plugin_id` equals the item's `pluginId`.
- Render: a plugin item draws its renderer's view, built once per item id and data hash and dropped when the entry goes (prune on `grouper.shifted()`). With no matching renderer, draw "Plugin timeline item unavailable." in `foreground_muted` with `SPACE_2` vertical padding, replacing the "plugin" note of `render_entry` (`lib.rs:1185-1195`). `TimelineRenderInput.timestamp` is the source entry's timestamp.
- Steps: in `render_step` (`lib.rs:1686-1712`), a step item whose entry has a projection draws its plugin views in place of `render_edit` or the hidden call, always visible, as Electron shows plugin items and edits (`turn/view.tsx:453-469`). Entries without a projection keep today's rules; TASK-184 removes `render_edit`.
- Selection actions: when an assistant message's `TextViewState` holds a non-empty selection and `is_selecting()` is false, show a toolbar of the active selection actions centered above the top edge of that message's text bounds (Planner call: gpui-base gives the view bounds, not a selection rectangle), clamped inside the timeline. Toolbar: `popover` background, 1 px `border_accent`, radius `RADIUS_LG`, padding and gap `SPACE_1`, `shadow(Md)`. Buttons: title only, `FONT_SM` `foreground`, padding `SPACE_1` by `SPACE_2`, radius `RADIUS_MD`, role button. A press clears the selection, then calls `on_select` with `AssistantSelection`: `text` is the Markdown source of `selected_source_range` when it is `Some`, else `selected_text()`; `message_id` is the item's `messageId`, else `seq:<seqStart>`; `workspace_id` is the agent's `workspace_id`. With no active action, no toolbar.
- `reveal_passage` scrolls the list to the row of the message whose id matches (same id rule), and with `text` that matches once in the message source, highlights it with `set_range_highlights` in `status_warning` for 2500 ms. Text with no match or several matches only scrolls. A request before the history loads waits up to 10 s; a message that is still not found shows "That message isn't loaded in this chat" with `window.push_notification`.
- Find ring: `find_bar.rs:353` uses `focus_ring(t.accent)`; width and offset stay.
- `TimelineEvent` and `TimelineView::new` stay unchanged. Every new button gets a role and a label. Keep each rule in a pure function and test it (MEMORY 2026-10-16).

Expected result:

- With an active plugin that transforms `tool_call` edits into `edit-diff` items and renders them, each edit in a step shows the plugin view instead of the built-in edit row.
- A daemon plugin item with a matching renderer shows that view; without one, the unavailable text.
- Cases:
  - Two transformers for `tool_call`; the first returns `None` -> the second's result is used.
  - Result with `source: First` and `text` on an `assistant_message` -> the message shows the new text, then the plugin items.
  - `source: Last` on a `tool_call` with `text` -> the call shows unchanged after the items.
  - `items: []` with no `source` -> the entry is hidden; grouping is unchanged.
  - Kind `"Bad Kind"` -> a warning and the entry drawn as without plugins.
  - A label change that turns the transformer off -> every entry is projected again once, then only changed entries.
  - Selection "foo" in a message, then a toolbar press -> the selection clears and `on_select` gets the text and message id.
  - `reveal_passage` with text found twice -> scroll only, no highlight; with an unknown id after load -> the notification.

Anti-goal: per-flush transform work stays in proportion to the change: on a 20,000-entry timeline with one `tool_call` transformer, appending one entry runs the transformer once and the projection step takes under 2 ms in a debug test; a revision change runs it once per matching entry; tripwire; read before the first change, after the projection cache lands, and at completion.
