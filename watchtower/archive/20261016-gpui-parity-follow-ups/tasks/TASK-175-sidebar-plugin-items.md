# TASK-175 Sidebar plugin items, sections, filters, and menus

Group: E (writes `crates/sidebar`)
Class: code

## Brief

Goal: Draw every sidebar contribution of the active plugins natively with Electron's look: nav rows, sections under the project list, project filters with their title and swipe, project menu items, and the Add project flow that tells filters about a new project.

Change: the sidebar shows only Search, the project tree, and a Settings icon -> plugin nav rows after Search, plugin sections above the footer, projects hidden by plugin filters with the filter title over the list, plugin items in the project menu, and an Add project button that runs `on_project_added`.

Boundaries:

- Follows [ADR-0045](watchtower/decisions/ADR-0045-native-rust-plugin-clients-over-webview-panes-or-shared-logic.md): read contributions only from `PluginHost::index`; draw nothing for a plugin the host does not report active. Rebuild on `PluginHostEvent::ContributionsChanged`, `SidebarFilterChanged`, and `PluginStateChanged` (a filter title, a menu item, or a disabled state may change), never per frame.
- Keep `SidebarEvent` unchanged, because `crates/app/src/shell.rs:241-246` matches it exhaustively. Emit the new requests as a second event type, `SidebarPluginEvent`, through a second `EventEmitter` impl (Planner call, as TASK-162 did for the explorer). Keep `Sidebar::new` and `set_selected_workspace` working as today.
- Keep `model::build_rows` and every existing public model item. Add filtering as new pure functions; the existing tests in `crates/sidebar/tests/model.rs` pass unchanged.
- Nav rows: after the Search row of `render_nav` (`sidebar.rs:779-816`), in index order. Compact row: icon `ICON_SM`, min height 28, gap `SPACE_2`, padding `SPACE_1` by `SPACE_2`, radius `RADIUS_LG`, label `FONT_BASE` in `foreground_muted`, `foreground` and `surface_sidebar_hover` when hovered or active. A press with `action` calls `on_press` with the selected workspace id; a press without `action` emits `SidebarPluginEvent::OpenSurface`. With `requires_workspace` and no selected workspace the row is disabled at half opacity.
- Planner call: `new_workspace_panel` on a sidebar action is ignored. No ported plugin sets it on a sidebar item (only watchtower-board, on a composer pill), and the sidebar cannot see the New workspace screen.
- Active row: the row of the surface the app reports through `set_active_surface` uses the hover colors, as Electron marks the row whose route is open.
- Filters: a project is hidden when any filter's `is_visible` returns false. `SidebarProject.view_key` comes from `Client::project_view_key`, `project_ids` holds the project id. Hidden projects drop their workspaces too, pinned ones included. When filters hide every project, show no `Row::Empty` onboarding row (Electron `sidebar-workspace-list.tsx:2433`).
- Title: the first non-empty trimmed filter title replaces "Workspaces" in `render_section_title` (`sidebar.rs:898`): `FONT_SM`, `foreground_muted`, one line.
- Swipe: a horizontal trackpad scroll over the project list fires one swipe per gesture: accumulated `|x| >= 28` and `|x| >= 1.5 * |y|`; a quiet gap over 120 ms, a reversal, or a fresh push after 160 ms starts a new gesture; line deltas count 16 px. `x > 0` is `SwipeDirection::Next`, as Electron's `1`. Call every filter's `on_swipe`; ignore a scroll with a mouse button held. A swipe never scrolls the list vertically.
- Slide: on `SidebarFilterChanged { direction: Some(..) }` the list slides out over 65 ms (ease-in) toward the opposite side, then in over 105 ms (ease-out) from the swipe side, with opacity 1 -> 0 -> 1. A second change during a slide applies at once. Never toggle `display` from hover (MEMORY 2026-10-16).
- Project menu: plugin items follow "Copy path" in `render_project`'s menu (`sidebar.rs:533-551`), in index order, title only, no icon. `disabled` greys the item, `checked` shows a trailing `Check`. An item with `items` opens a submenu, with the first checked child's title as its trailing value. The current `menu_item` helper takes a `&'static str` label, so add a helper for owned labels.
- Sections: below the project list and above the footer, each a cached `AnyView` from its `ViewFactory<()>`, built once per contribution and dropped when the contribution goes. No padding or border of their own.
- Add project (Planner call, from Electron's footer): an "Add project" button on the left of the footer, with `FolderPlus` at `ICON_SM`, min height 32, gap `SPACE_2`, padding `SPACE_1_5` by `SPACE_2`, radius `RADIUS_LG`, label `FONT_BASE` muted, hover `surface_sidebar_hover`. It opens the system folder picker (directories only), calls `add_project`, then awaits each filter's `on_project_added` in index order. A filter `Err` shows its text with `window.push_notification` and stops; the project stays added. On success emit `SidebarPluginEvent::ProjectAdded`. The GitHub search pages of Electron's flow stay out.
- New views use `bachuc_theme` tokens and `bachuc_icons` icons. Every new row, button, and menu item gets a role and a label.
- Keep each rule in a pure function and test it: GPUI view crates have no headless test context here (MEMORY 2026-10-16).

Expected result:

- With an active plugin that adds a sidebar item, its row shows under Search and opens its surface or runs its action.
- A filter that hides a project removes it and its workspaces; its title replaces "Workspaces".
- Cases:
  - No active plugin -> the sidebar looks as today, with only the new Add project button.
  - Two filters, one hides project A -> A is hidden; a filter that hides every project -> no empty onboarding row.
  - Two filters with titles `""` and `"Space 2"` -> the header reads "Space 2"; no title -> "Workspaces".
  - Wheel deltas `(10, 0)`, `(10, 2)`, `(10, 1)` within 120 ms -> one `Next`; a gap of 130 ms between pushes -> the count restarts; `(-30, 0)` -> one `Previous`; `(20, 20)` -> none.
  - A `requires_workspace` item with no selected workspace -> disabled; with one -> `on_press(Some(id))`.
  - A menu item with children `[a, b(checked)]` -> a submenu whose trailing value is `b`'s title.
  - Add project with a filter that returns `Err("full")` -> a notification "full" and no `ProjectAdded`.

Anti-goal: the sidebar row rebuild stays in proportion to the change: a 500-project tree with two filters rebuilds its rows in under 10 ms in a debug test, and a `SidebarFilterChanged` with no visibility change leaves the row list equal; tripwire; read before the first change, after filters land, and at completion.
