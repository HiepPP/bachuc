## Contract

- `bachuc_sidebar::Sidebar::new(client: Entity<Client>, window: &mut Window, cx: &mut Context<Sidebar>) -> Sidebar`, as in the spec.
- `Sidebar::set_selected_workspace(&mut self, workspace_id: Option<String>, cx: &mut Context<Sidebar>)`.
- `bachuc_sidebar::SidebarEvent { OpenWorkspace { workspace_id: String }, OpenSettings, OpenCommandCenter }`. The sidebar also marks the clicked workspace selected itself.
- The view is `h_full`, `w = SIDEBAR_WIDTH` at start, and resizes between `SIDEBAR_MIN_WIDTH` and `SIDEBAR_MAX_WIDTH` by its own drag handle. Put it as the first child of a horizontal flex; the parent supplies the rest.
- Extras: `bachuc_sidebar::model` (pub) holds the tested logic: `build_rows`, `bucket_for_agent`, `most_urgent`, `archive_prompt`, `changed_range`, `clamp_width`, `identity_color`, `project_initial`, `workspace_label`.
- Tree: optional `Pinned` section (workspaces with `pinned`, daemon order, each led by its project icon), then `Workspaces` heading, then project rows with unpinned workspaces. Workspaces keep the daemon order. A group over 20 workspaces gets Show more / Show less. Collapse is per project and for Pinned, in memory only.
- Status per workspace is the most urgent bucket of its agents (needs input, failed, running, attention, done). A collapsed project shows its most urgent bucket on its icon.
- Nav: Search (emits `OpenCommandCenter`) at the top; Settings (emits `OpenSettings`) in the footer.
- Workspace menu: Copy path, Rename workspace (dialog), Mark as unread (only when the bucket is done, as `canMarkUnread`), Pin to top / Unpin, Archive. Project menu: Copy path.
- Archive: reads `checkout_status`; changed files give a confirm alert ("Archive "name"?" with the added and deleted line counts); none, or a failed status read, archives at once. The row shows "Archiving..." until it leaves the tree or 10 s pass.

## Gaps

- Left out, as the spec says: schedules, sessions (history), and New workspace nav rows; the display menu on the "Workspaces" heading; the empty state buttons (open project, import).
- Archive risk covers changed files only. The "ahead of remote" case is a recorded gap: the client does not expose it.
- `requiresAttention` and the attention reason are not in `AgentSummary`, so the Attention bucket never appears and a finished unseen agent reads as Done. Mark as unread therefore shows only for done workspaces, as in Electron when nothing needs looking at.
- Project menu has only Copy path; other Electron project actions (new worktree, remove) are out of scope.

## Lessons

- A gpui-kit `Icon` has no `group_hover`; wrap it in a `div` and put the group style on the div.
- A popup menu anchor must implement `Selectable` and `DropdownMenu`; `KebabButton` in `src/sidebar.rs` is the template. Never put a mouse-down listener that calls `stop_propagation` on the trigger: GPUI runs the child's listener before the popover wrapper's, so the menu never opens (fixed in Fix Round 1).
- Dialogs need `window.open_dialog` / `open_alert_dialog` from `WindowExt`. `gpui_kit::open_window` wraps the view in the gpui-base `Root`, which already draws the dialog, notification, and popover plugin layers; the app adds no layer.
- The sidebar listens to `ClientEvent::{Connected, Disconnected, AgentsChanged}` and `DirectoryEvent::ProjectsChanged`; `Sidebar` needs a strong `Entity<Client>`.

Differences that stay:

- Diff counts are the uncommitted changes. Electron's `diffStat` is a shortstat against the base ref, so a branch with commits ahead of its base shows a bigger number there. They match for a main checkout (`~/.claude`: both +55 -35).
- A clean checkout shows nothing; Electron shows `+0 -0` when the daemon sends a zero `diffStat`.
- Pinned rows keep the tree order; Electron sorts them by `pinnedAt`, newest first, which the client does not expose.
- A user drag order (`applyStoredOrdering`) is not ported; GPUI has no drag reorder.
